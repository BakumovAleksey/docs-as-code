# Требования

## User Stories

### US-01. Классификация обращения

Как оператор поддержки,
я хочу автоматически получать категорию обращения,
чтобы быстрее направлять его нужной группе.

Критерии приёмки:
- система принимает текст обращения;
- после обработки отображается определённая категория;
- если классификация невозможна, пользователь получает сообщение об ошибке.

### US-02. Отправка обращения

Как пользователь,
я хочу отправить текст своего обращения,
чтобы получить помощь от технической поддержки.

Критерии приёмки:
- пользователь может ввести и отправить текст обращения;
- после отправки обращение сохраняется в системе;
- пользователь получает подтверждение отправки.

### US-03. Просмотр результата классификации

Как оператор поддержки,
я хочу видеть категорию обращения и уверенность модели,
чтобы принять решение о дальнейшей обработке.

Критерии приёмки:
- оператор видит категорию обращения;
- оператор видит уверенность модели;
- оператор может передать обращение на ручную обработку.

## Use Case

### UC-01. Классификация обращения

**Актор**: оператор поддержки

**Цель**: определить категорию обращения.

**Предусловие**: пользователь отправил обращение.

**Основной сценарий**:

1. Оператор открывает обращение.
2. Система передаёт текст ML-модели.
3. ML-модель определяет категорию.
4. Система получает результат.
5. Оператор видит определённую категорию.

**Альтернативный сценарий**:

Если модель не может обработать текст, система сообщает,
что требуется ручная классификация.

**Результат**: категория обращения определена или обращение передано
на ручную обработку.
