# Риски и ограничения

## Потенциальный bias

**Риск 1.** Данные для обучения созданы машинным переводом с английского,
в них отсутствуют тексты реальных обращений в поддержку.

Возможное последствие: качество определения категорий на реальных
обращениях может быть ниже заявленной метрики NLI (0,803 для русского
языка на XNLI).

Что можно сделать: сформировать тестовую выборку из размеченных
обращений проекта и оценить качество по каждой категории отдельно.

**Риск 2.** Тонкая настройка модели выполнялась на данных NLI, а не на
классификации категорий; список категорий задаётся на этапе инференса.

Возможное последствие: модель может путать близкие по смыслу категории
(например, account и payment) либо выдавать высокую уверенность при
неверной категории.

Что можно сделать: устанавливать порог уверенности, ниже которого
обращение передаётся на ручную обработку (соответствует
альтернативному сценарию UC-01).

## Этические риски

**Риск 1.** В текстах обращений могут присутствовать персональные
данные (имена, адреса, номера заказов).

Последствие: утечка персональных данных при передаче текста модели.

Способ снижения риска: очищать или маскировать персональные данные перед
передачей текста в ML-модель; ограничить доступ к результатам анализа.

**Риск 2.** Автоматическая классификация может ошибаться и направлять
обращение не в ту группу поддержки.

Последствие: задержка обработки обращения и ухудшение качества
поддержки для пользователя.

Способ снижения риска: всегда отображать оператору категорию и
уверенность модели; предусмотреть ручную переклассификацию
(альтернативный сценарий UC-01).
