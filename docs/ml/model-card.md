## Использование в проекте

Модель выполняет определение категории обращения: payment, account,
technical, order.

Текст обращения передаётся модели через API (см. `POST /classifications`
из практикума 3) вместе со списком кандидатных категорий. Модель
сравнивает текст с каждой категорией и возвращает метку с наибольшей
уверенностью. Результат (категория и уверенность) сохраняется системой
и отображается оператору через `GET /classifications/{id}`.

Zero-shot подход позволяет использовать модель без обучения: список
категорий задаётся на этапе инференса, а не фиксируется при обучении.
При изменении набора категорий достаточно изменить список в запросе.

## Входные данные

Текст обращения (посылка) и гипотеза вида «Это обращение относится к
категории {категория}» для каждой кандидатной категории.
Максимальная длина последовательности — 512 токенов.

## Выходные данные

Для каждой категории — вероятности entailment / neutral / contradiction.
Итоговая категория определяется по наибольшей вероятности entailment;
уверенность — нормализованная оценка по категориям.

## Метрики качества

Указанные авторами модели (accuracy):

- XNLI (тест), русский язык — 0,803;
- XNLI (тест), среднее по 15 языкам — 0,808;
- MultiNLI (matched) — 0,857; MultiNLI (mismatched) — 0,856;
- FEVER-NLI — 0,761; LingNLI — 0,788; WANLI — 0,732; ANLI — 0,537.

## Ограничения

Указанные авторами модели:

- обучающий датасет создан с использованием машинного перевода, что
  снижает качество данных для сложной задачи NLI;
- качество на языках, не входивших в данные NLI-тонкой настройки,
  ниже, чем на языках обучающей выборки.

Потенциальные ограничения для проекта:

- метрики указаны для задачи NLI, а не для классификации категорий
  обращений — качество на домене поддержки необходимо проверять
  отдельно;
- категории payment, account, technical, order сформулированы на
  английском языке; для русскоязычных обращений гипотезы целесообразно
  формулировать на русском языке и проверить качество на выборке.

## Не рекомендуется использовать

- без оценки качества на реальных обращениях поддержки;
- для длинных текстов сверх 512 токенов без усечения;
- как единственный источник решения о маршрутизации критичных
  обращений без возможности ручной проверки.
